# 部署步驟

第一次做大概 20 分鐘。照順序做，每一步都有可以確認的結果。

有兩個部分要各自架起來：

| 部分 | 放哪 | 你要做的事 |
|---|---|---|
| 後端 | Google Apps Script + 試算表 | 建試算表、貼程式碼、部署 |
| 前端 | GitHub Pages | 填一行網址、開啟 Pages |

---

## 第一部分：後端（Google Apps Script）

### 1. 建立試算表

1. 開 [Google 試算表](https://sheets.new)，建立一份新的空白試算表
2. 命名為「娃娃機管理系統資料」（名字隨意）
3. 從網址列複製**試算表 ID**——就是 `/d/` 和 `/edit` 中間那一長串：

   ```
   https://docs.google.com/spreadsheets/d/【這一段就是試算表 ID】/edit
   ```

> ⚠️ 這份試算表**不要開共用連結**。所有帳號密碼的雜湊值都存在裡面，
> 誰拿到試算表就等於拿到整個系統的資料。

### 2. 建立 Apps Script 專案

1. 開 [script.google.com](https://script.google.com/home) → 「新增專案」
2. 專案命名為「娃娃機管理系統」
3. 左邊齒輪「專案設定」→ 勾選「在編輯器中顯示 appsscript.json 資訊清單檔案」

### 3. 貼上程式碼

**只需要貼兩個檔案**，不用一個一個開：

| repo 裡的檔案 | 在 GAS 裡怎麼做 |
|---|---|
| `appsscript.json` | 已經存在，把內容整個換掉 |
| `apps-script/dist/Code.gs` | 已經存在（預設叫 `Code.gs`），把內容**整個**換掉 |

`apps-script/dist/Code.gs` 是把後端所有邏輯（資料層、登入、業務邏輯、報表、
按季自動封存、API 路由、自我測試）合併成一份的完整檔案，貼這一份就等於貼齊了
全部功能——GAS 本來就是把同一個專案裡的所有指令碼檔案當成同一個共用作用域
執行，分成好幾個檔案或合成一個檔案，跑起來完全一樣，合併只是省掉「開好幾次
新增指令碼」這個步驟。

貼完按 💾 儲存。

> 想看程式碼是怎麼分模組寫的（資料層 / 認證 / 業務邏輯 / 報表 / 按季自動封存 /
> 路由 / 測試），到 `apps-script/` 資料夾看那幾個分開的原始檔——那才是真正維護、
> 之後會被改動的版本；`dist/Code.gs` 是每次改完用 `npm run bundle` 自動重新
> 產生的成品，不要手動編輯它。

### 4. 設定試算表 ID

1. 左邊齒輪「專案設定」→ 最下面「指令碼屬性」→「新增指令碼屬性」
2. 屬性名稱 `SPREADSHEET_ID`，值貼上第 1 步複製的試算表 ID
3. 再新增一個（**選擇性**）：屬性名稱 `INITIAL_ADMIN_PASSWORD`，值填你想要的管理員密碼
   （不設的話系統會隨機產生一組，在下一步顯示給你）

### 5. 執行 setup 初始化

1. 編輯器上方函式下拉選單選 **`setup`** → 按「執行」
2. 第一次會跳出授權：「查看您的 Google 帳戶」→ 選你的帳號 →
   「進階」→「前往 娃娃機管理系統（不安全）」→「允許」
   （這是 Google 對未經驗證的個人指令碼的標準提示，這支程式是你自己貼的）
3. 執行完成後，看下方「執行紀錄」，會看到：

   ```
   === 管理員帳號已建立 ===
   帳號：admin
   密碼：xxxxxxxxxxxx
   ========================
   ```

   **把這組密碼記下來**，等一下要用。

4. 回頭看試算表，應該多出 10 個分頁（帳號、機台、紀錄…），頁籤名稱與表頭都是中文排好了

> 如果你的試算表是舊版程式碼建立的（頁籤名稱是英文的 `Users`、`Machines`，
> 表頭還是英文的 `user_id`、`display_name` 那種），重新執行一次 `setup` 就會自動
> 把頁籤名稱與表頭都換成中文，**不會動到任何一筆既有資料**——頁籤是直接原地改名，
> 表頭只覆寫第一列的標題文字，帳號、機台、紀錄都原封不動。
>
> 如果你的試算表在「入幣改成碼表登錄」上線期間記過帳，`setup` 也會自動偵測並修正
> 那段期間欄位被插錯位置造成的資料錯位（操作人／建立時間被讀錯的問題），
> 執行紀錄會顯示修正了幾筆，同樣不會遺失任何資料，金額也從頭到尾沒被影響過。
>
> `setup` 還會順便裝一個「每月自動封存檢查」的時間觸發器（把上一季以前的舊紀錄
> 搬去封存分頁，見 `guide/SHEETS.md`「按季自動封存舊資料」）。第一次執行可能會
> 多跳一次授權畫面（GAS 對「建立時間觸發器」這個動作的標準要求），照步驟 2 一樣
> 允許就好；已經裝過的話重新執行 `setup` 不會重複裝。

### 6.（選擇性）跑自我測試

函式下拉選單選 **`runSelfTest`** → 執行 → 看執行紀錄（`runSelfTest` 已經包含在 `dist/Code.gs` 裡）。

它會另外開一份暫時的試算表跑幾十項測試，跑完自動丟進垃圾桶，**不會碰到你的正式資料**。
全部通過就代表後端邏輯正常。

### 7. 部署成網頁應用程式

1. 右上「部署」→「新增部署作業」
2. 齒輪圖示 → 選「網頁應用程式」
3. 設定：
   - 說明：`v1`
   - 執行身分：**我（你的帳號）**
   - 具有存取權的使用者：**任何人**
4. 「部署」→ 複製**網頁應用程式網址**（結尾是 `/exec`）

> 這個網址公開沒關係——沒有帳號密碼就拿不到任何資料，
> 所有 API 都要有效的登入 token 才會回應。

> ⚠️ **之後每次改 GAS 程式碼，都要「部署」→「管理部署作業」→ 編輯（鉛筆）→
> 版本選「新版本」→ 部署。** 網址不會變，但不選新版本的話改動不會生效。
> 這是最常見的「我明明改了怎麼沒反應」原因。

## 第二部分：前端（GitHub Pages）

### 8. 填入後端網址

編輯 `docs/config.js`，把第 7 步的網址貼進去：

```js
window.APP_CONFIG = {
  GAS_API_URL: 'https://script.google.com/macros/s/AKfycb.../exec'
};
```

存檔，commit 並 push。

### 9. 開啟 GitHub Pages

1. GitHub 上打開這個 repo → **Settings** → 左邊 **Pages**
2. Source 選 **Deploy from a branch**
3. Branch 選你的分支，資料夾選 **`/docs`** → Save
4. 等一兩分鐘，頁面上方會出現網址：`https://<你的帳號>.github.io/wei/`

> ⚠️ **repo 必須是 public**。GitHub 免費方案的 private repo 不能發佈 Pages。

### 10. 裝到手機

**iPhone（Safari）**
1. 用 Safari 開上面那個網址（**一定要 Safari**，Chrome 加的主畫面圖示不會全螢幕）
2. 下方「分享」按鈕 → 往下捲 →「加入主畫面」→ 加入
3. 從主畫面的圖示啟動 → **應該看不到網址列**，跟一般 App 一樣

**Android（Chrome）**
1. 用 Chrome 開網址
2. 右上「⋮」→「安裝應用程式」或「加到主畫面」
3. 從桌面圖示啟動，同樣沒有網址列

### 11. 第一次登入

用第 5 步拿到的帳號密碼登入，然後：

1. **⚙ 系統管理 → 帳號 → 改密碼**，把隨機密碼換成你記得住的
2. **⚙ 系統管理 → 機台 → ＋ 新增機台**，把你的機台建進去
3. **⚙ 系統管理 → 獎型**，調整成你實際的獎品名稱與成本
4. 進任一台機台 →「出幣」→「✎ 編輯」，把快捷金額改成你常用的；
   入幣改用碼表登錄，預設每格 $100，不合用的話在「入幣」面板的「✎ 編輯」調整費率
5. **⚙ 系統管理 → 帳號 → ＋ 新增帳號**，建巡邏人員與台主的帳號
6. **⚙ 系統管理 → 台主授權**，勾選每個台主看得到哪幾台

## 常見問題

**改了 GAS 程式碼卻沒反應**
→ 沒有部署新版本。「部署」→「管理部署作業」→ 鉛筆 → 版本選「新版本」→ 部署。

**按「匯出 Excel」失敗，沒看到授權畫面**
→ 匯出改成產生真正的 .xlsx 檔之後，後端需要暫時建立一份試算表來套版、
轉檔、再刪掉，第一次用到這個權限時 Google 需要另外授權。但部署好的
Web App 是背景呼叫，沒有互動畫面能跳出「允許」——授權畫面只有在編輯器
裡**手動執行函式**時才會顯示，所以直接在 App 上按會直接失敗。
解法：編輯器函式下拉選單選 **`authorizeExportXlsx`** → 執行 → 這次會跳出
「這個應用程式尚未經 Google 驗證」畫面 → 點「進階」→「前往（不安全）」→
「允許」。跑完看執行紀錄印出「授權沒問題」，回 App 再按一次「匯出 Excel」
就正常了。這個函式故意只做最少的事（建一份空試算表、打一次匯出網址、
刪掉），幾秒鐘就跑完，**不要**為了這件事去跑 `runSelfTest`（見下一條）。

**執行 `runSelfTest` 卡在「Exceeded maximum execution time」**
→ 這是已知限制，不代表程式有問題：`runSelfTest` 在真正的 Google 試算表上
要跑 90 幾項測試，每一項都要真的連線讀寫 Sheets，跟本機測試（`npm test`，
幾秒鐘跑完）不是同一回事，筆數多了容易超過 Apps Script 手動執行 6 分鐘的
上限，直接被砍斷，不是資料壞掉或程式錯誤。正確性已經由 `npm test`（後端）
與 `npm run test:e2e`（前端）在本機驗證過，`runSelfTest` 頂多當作偶爾抽查
用，不用每次改完都在正式試算表上完整跑一輪，也不用擔心跑到一半被砍斷。

**登入頁一直顯示「帳號或密碼錯誤」，明明帳號密碼沒打錯**
→ 檢查「專案設定 → 指令碼屬性」裡 `SPREADSHEET_ID` 的值，是不是跟你平常
在用的那份試算表網址不一樣。曾經發生過的成因：`runSelfTest()` 執行期間
會暫時把這個設定值改指到一份剛建立的空白測試試算表，跑完再改回來；但
如果那次執行剛好被上面那條「6 分鐘執行上限」砍斷，改回來那段程式碼
根本沒機會執行，`SPREADSHEET_ID` 就會永久卡在測試用的空試算表上，
造成正式站台（包含登入）都查不到真實資料。**這個成因已經在程式碼裡
修好**（`runSelfTest()` 改用執行期變數而非直接覆寫這個持久設定，就算
中途被砍斷也不會外洩），舊版程式碼才會有這個問題。如果真的又發生：
把 `SPREADSHEET_ID` 手動改回你正式在用的試算表 ID 即可，不用重新部署
（Script Properties 是設定值，改了立刻生效）；順手到雲端硬碟找找有沒有
殘留的「【自我測試】娃娃機管理系統 ...」試算表，那是被砍斷的那次留下的，
確認不是正在用的之後可以直接刪掉。

**前端顯示「還差最後一步」**
→ `docs/config.js` 的 `GAS_API_URL` 還是空的，或 push 後 Pages 還沒重新發佈（等一兩分鐘）。

**前端顯示「連線失敗」**
→ 檢查 GAS 部署的「具有存取權的使用者」是不是設成「任何人」。
設成「僅限自己」的話，前端連不上。

**改了前端但手機還是舊畫面**
→ Service Worker 快取住了。把 `docs/sw.js` 的 `CACHE_VERSION` 加一號再 push，
使用者就會收到更新提示。**每次改前端都要做這件事**。

**忘記管理員密碼**
→ 打開試算表的 `Users` 分頁，把那一列的 `password_hash` 和 `salt` 兩格清空，
再回 GAS 執行一次 `setup`（它會認出這個管理員帳號密碼是空的，重新產生一組密碼、
印在執行紀錄裡，並讓這個帳號原本的登入全部失效——不是只在完全沒有管理員帳號時
才會重建，帳號本身、其他資料都不會被動到）。

**手機被撿到了**
→ 打開試算表的 `Sessions` 分頁，把該帳號的列全部刪掉，那些裝置就會立刻被登出。
再用系統管理改一次密碼更保險。

**紀錄越來越多會不會變慢**
→ 目前的做法是每次請求把 `Records` 整張讀進記憶體再彙總，效能是跟著
累計總筆數變慢，不是跟著查詢區間。系統會**每月自動檢查一次**（執行過
一次 `setup` 就會裝好，不用手動設定），把「目前這一季」以前的資料搬到
獨立的封存分頁（例如「封存_2026Q1」），讓 `Records` 只留最近一季，
讀取速度不會隨著開店年數一直往上疊加。資料沒有被刪除，只是搬到別的
分頁；機台詳細頁的「累計淨收益」不會因此掉下去；報表／匯出對帳表 選到
已封存的舊區間會明確報錯，不會默默算出不完整的數字。詳見
`guide/SHEETS.md`「按季自動封存舊資料」。

**測試完了，正式上線前想把測試期間的資料清空**
→ 編輯器函式下拉選單選 **`clearTestData`** → 執行 → 看執行紀錄確認清了幾筆。
會清空「紀錄」「每日手動帳目」「營業日」三個分頁，機台上的「封存前累計」欄位
（`carry_in` 等）會歸零；**機台本身**（名稱、位置、顏色、分類、圖案、排序）、
快捷金額、獎型、入幣費率、帳號與授權都不會被動到。**這是不可逆的動作**，
執行前建議先把整份試算表複製一份備份（試算表選單「檔案 → 建立副本」）。
如果測試期間有觸發過自動封存，「封存_2026Q1」這類分頁不會被這支函式清掉，
要清的話自己手動刪除那些分頁。
